Distribucion: Claude Code por `.claude-plugin/` (plugin `chiche`, antes `chichex-skills`; el marketplace publica tambien `chichex-skills` como alias de una instalacion vieja); Codex por el marketplace `.agents/plugins/marketplace.json` y el manifest `.codex-plugin/plugin.json`, que apunta solo a `codex/`; Pi por el Pi Package (`pi install git:github.com/chichex/chiche`) o por las copias legacy de `install.sh`. `VERSION` es la unica fuente de version y `package.json` y `.codex-plugin/plugin.json` la repiten.
El contrato y los artefactos trackeados viven en `.chiche/`; los borradores locales y el log de eventos, en `<git-common-dir>/chiche/`. Un `.sdd/` o un `<git-common-dir>/sdd/` de un repo sin migrar se sigue leyendo, y `chiche-init --update` lo migra. Los alias `sdd-*` se retiraron en 4.0.0.
El dial de autonomia (6.0.0) son tres controles: la confianza de `grill` y `chiche-spec` (0 a 100, `--confidence <n>`), la posicion del run (`ask`, `pr`, `pr-reviewed`, `--mode`) y la cadena (`--until pr`, que solo encadena). La historia de cada capa esta en `## Decisiones humanas` y en git.
La publicacion configurable (6.1.0, issue #134, capa 1) es la seccion `## Publicacion` del contrato (`specs`, `carpeta`, `repo` y `crear issue`), que `chiche-init` pregunta despues de la posicion del run, escribe entre `## Ambientes` y `## Verificacion autonoma` y verifica sin ejecutar la plantilla; el bloque `publication-resolve` la lee de la raiz operativa con defaults. Desde 6.2.0 (issue #134, capa 2) `chiche-spec` aplica `specs` en su Destino (`auto` es la regla de siempre; `issue` y `local` fuerzan el destino, y una creacion fallida cae a `<carpeta>/specs/` con aviso), `grill`, `chiche-spec`, `chiche-run`, `issue-triage` y `code-review` leen `<carpeta>/` primero y escriben lo nuevo ahi, `chiche-land` resuelve una copia sin trackear de esa carpeta como ya aterrizada, y en Pi `resolveArtifactDirs` expone `declared` y `artifactWriteDir` (la carpeta declarada, o el common-dir) para `grill_session` y `persist_sdd_spec`; la identidad events-v1 no cambia. ## Gaps
- `## Publicacion` (issue #134), pendientes de las reviews del stack #141: una plantilla `crear issue` con `|` (`\|` en la tabla) la trunca el `cut -d'|'` del comando canonico y el valor truncado puede pasar la validacion (#138-5; la doctrina pide la plantilla sin `|`); en Pi, con un `repo` declarado distinto del de `origin`, `persist_sdd_spec` ata todo `issueNumber` al repo declarado y no puede publicar sobre un issue de `origin` (#140-5: haria falta un repo por destino, restringido a los dos permitidos); la seccion se lee del contrato de la raiz operativa (inferencia asumida de la spec), asi que un branch puede cambiar `crear issue`, mientras la stop list que la frena se lee del branch default.
- La stop list matchea por substring sobre el comando completo: frena tambien un `git grep "gh pr merge"`, un `grep "pi install"` o un commit que nombre `install.sh pi`. Error aceptado hacia el lado seguro: anclar cada patron exige dos filas por `Pattern`, porque `|` no se permite.
- `gh stack` (extension `github/gh-stack`, v0.2.0 del 2026-10-02, GA de stacks 2026-10-06) se tomo del README de `github/gh-stack` (leido via la API de GitHub el 2026-10-08) y de las notas del grill. `gh stack` ya se ejecuto en vivo: merge atómico, `unstack --local` y `branch -d` en `pramaestudio/platform#59/#60` (los dos PRs comparten el merge `896153e`, verificado con `gh pr view` el 2026-10-09), y ahi `gh stack view --json` tenia un head viejo, asi que GitHub sigue mandando sobre el estado local. `sync`, `rebase` y `link` no tienen corrida en vivo registrada en este contrato: su conducta real sigue siendo la prueba humana CA-26 de la spec #66.
